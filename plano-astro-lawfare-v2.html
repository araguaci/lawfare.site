Decisão: JSON único. Para o lawfare-timeline — projeto solo com fluxo de adicionar entradas sequenciais — o split traz complexidade sem benefício real. Se o arquivo crescer além de 20MB (estimativa: ~3000+ entradas), revisar split por décadas.

Decisão crítica — busca com 1400+ entradas
✓ Solução escolhida: Pagefind

Pagefind é um indexador de busca estático criado especificamente para sites Astro/Jekyll/Hugo com muitas páginas. Roda após o build, indexa o HTML gerado, e entrega uma UI de busca com ~30KB de JS no cliente. Para 1400 páginas, o índice fica em ~500KB–1MB (servido em chunks, só o necessário por query).

✕ Fuse.js (descartado)
✕Carrega todo o JSON no browser: 8–15MB
✕Busca lenta em arrays de 1400+ objetos no cliente
✕Sem highlight de termos nos resultados
~Simples de implementar para volumes menores
✓ Pagefind (escolhido)
✓Indexa HTML estático pós-build — zero config
✓~30KB JS no cliente + chunks sob demanda
✓Highlight de termos, filtros por campo, ranking
✓Suporte nativo a português (stemming)
✓UI pronta ou API JS para UI customizada

Paginação obrigatória — 1400+ cards

Problema: renderizar 1400 cards em um único index.astro gera 2–4MB de HTML. Solução: 50 eventos por página → ~28–30 páginas de index.

// src/pages/pagina/[page].astro — paginação nativa do Astro --- export const getStaticPaths = (({ paginate }) => { import data from '../../data/assuntos.json'; const sorted = data.assuntos.sort( (a, b) => b.data_evento.localeCompare(a.data_evento) ); return paginate(sorted, { pageSize: 50, // 50 por página → ~28 páginas }); }) satisfies GetStaticPaths; const { page } = Astro.props; // page.data → eventos desta página // page.total → total de eventos // page.currentPage, page.lastPage → para UI de paginação --- // src/pages/index.astro — redireciona para /pagina/1 --- return Astro.redirect('/pagina/1'); ---
  • ↳URL structure: /pagina/1, /pagina/2... /pagina/28
  • ↳Páginas de categoria também paginadas: /categoria/lawfare/1
  • ↳Componente <Paginacao> com prev/next + números de página
  • ↳Canonical tags corretas em cada página para SEO

// scripts/audit-json.mjs — rodar localmente antes do build import { z } from 'zod'; import data from '../src/data/assuntos.json' assert { type: 'json' }; const EventoSchema = z.object({ id: z.number(), titulo: z.string().min(1), data_evento: z.string().regex(/^\d{4}-\d{2}-\d{2}$/), data_iso: z.string(), categoria: z.string(), tags: z.array(z.string()), descricao: z.string(), relevancia: z.enum(['alta', 'media', 'baixa']), fontes: z.array(z.string()), pessoas_envolvidas: z.array(z.string()), prioridade: z.number(), id: z.number().positive(), }); const errors = []; const ids = new Set(); data.assuntos.forEach((evt, i) => { // Checar IDs duplicados if (ids.has(evt.id)) errors.push(`ID duplicado: ${evt.id} (index ${i})`); ids.add(evt.id); // Validar schema const result = EventoSchema.safeParse(evt); if (!result.success) errors.push(`ID ${evt.id}: ${result.error.issues.map(e => e.message).join(', ')}`); }); if (errors.length) { console.error(`\n❌ ${errors.length} erros encontrados:\n`); errors.forEach(e => console.error(' ', e)); process.exit(1); } else { console.log(`✓ ${data.assuntos.length} entradas válidas. Próximo ID: ${Math.max(...[...ids]) + 1}`); }
  • 01Rodar o script de auditoria — resolver todos os erros antes de iniciar o Astro
  • 02Confirmar IDs sequenciais sem gaps ou duplicatas
  • 03Normalizar os enum de categoria e relevancia — listar todos os valores únicos
  • 04Adicionar ao package.json o script "audit": "node scripts/audit-json.mjs"
