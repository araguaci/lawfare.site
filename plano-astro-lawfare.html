Plano de Migração — v1.0

Jekyll → Astro
lawfare-timeline

Substituição completa do stack de publicação: de Jekyll/Chirpy (build lento, sem tipagem) para Astro com content collections e fonte de dados .json centralizada. Build 10–20× mais rápido. Deploy instantâneo na Vercel.

Stack atualJekyll + Chirpy + Liquid

DeployVercel (mantido)

Por que migrar para Astro
✕ Jekyll — Problemas
✕Build lento: 1–5 min para 200+ posts
✕Ruby + Bundler: dependências frágeis, versões conflitam
✕Liquid sem tipagem — JSON integrado com gambiarra
✕HMR inconsistente no dev server
✕Filtros, paginação e busca = plugins externos frágeis
✕Vercel cache mal aproveitado — rebuild total a cada push
✓ Astro — Vantagens
✓Build 10–20× mais rápido (Vite, paralelo, incremental)
✓Node.js puro — sem Ruby, sem Bundler, sem gemset
✓Content Collections com schema Zod tipado nativo
✓HMR instantâneo + islands architecture
✓JSON como fonte primária: import data from './data.json'
✓Deploy Vercel: output SSG nativo, cache otimizado

02
Estrutura de dados — JSON como fonte única
Schema Zod, validação, tipos TypeScript
~3h

A abordagem correta para o seu JSON é usar o Astro Content Collections com loader de JSON — mais tipado, validado e suportado nativamente desde Astro 4.

Schema do objeto — baseado no seu JSON
campotipouso
idnumberID único sequencial — slug da URL
titulostring<title> da página + card
data_eventostringYYYY-MM-DD — filtro e ordenação
data_isostringISO 8601 — <time> semântico
categoriaenumFiltro principal: indecoro, corrupcao, lawfare...
tagsstring[]Tags de navegação cruzada
descricaostringMeta description + excerpt
relevanciaenumalta | media | baixa — destaque visual
fontesstring[]URLs de fontes — renderizadas como links
pessoas_envolvidasstring[]Tags de pessoas — links de busca futura
prioridadenumber1-5 — ordenação no feed
// src/content/config.ts — Content Collections com JSON loader import { defineCollection, z } from 'astro:content'; const eventosCollection = defineCollection({ type: 'data', // lê JSON/YAML, não markdown schema: z.object({ id: z.number(), titulo: z.string(), data_evento: z.string(), data_iso: z.string(), categoria: z.enum(['indecoro', 'corrupcao', 'lawfare', 'institucional', 'outros']), tags: z.array(z.string()), descricao: z.string(), relevancia: z.enum(['alta', 'media', 'baixa']), fontes: z.array(z.string()), pessoas_envolvidas: z.array(z.string()), instituicoes_envolvidas: z.array(z.string()), pais: z.string().default('Brasil'), valor_envolvido: z.string().optional(), prioridade: z.number().default(3), }) }); export const collections = { eventos: eventosCollection };
# Estrutura de arquivos para o JSON src/content/ └── eventos/ ├── data.json # arquivo principal com o array "assuntos" └── # ou múltiplos .json se quiser separar por ano

⚠️ O Astro Content Collections com type: 'data' espera um objeto por arquivo JSON. Para o array assuntos[], a solução é fazer um script de split (um JSON por evento) ou usar import direto no build.

03
Geração de páginas dinâmicas
getStaticPaths, layout base, templates
~4h

Astro gera uma página estática para cada entrada do JSON via getStaticPaths(). URL: /evento/[id]-[slug]

// src/pages/evento/[id].astro --- import type { GetStaticPaths } from 'astro'; import Layout from '../../layouts/Base.astro'; import eventoData from '../../data/assuntos.json'; export const getStaticPaths = (() => { return eventoData.assuntos.map(evento => ({ params: { id: String(evento.id) }, props: { evento } })); }) satisfies GetStaticPaths; const { evento } = Astro.props; --- <Layout title={evento.titulo} description={evento.descricao} date={evento.data_iso} > <article> <time datetime={evento.data_iso}>{evento.data_evento}</time> <h1>{evento.titulo}</h1> <p>{evento.descricao}</p> <ul> {evento.fontes.map(f => f !== 'N/A' && ( <li><a href={f} target="_blank">{f}</a></li> ))} </ul> </article> </Layout>
// src/pages/index.astro — feed com filtros --- import Layout from '../layouts/Base.astro'; import EventoCard from '../components/EventoCard.astro'; import data from '../data/assuntos.json'; // Ordenar por data desc + prioridade const eventos = data.assuntos .sort((a, b) => b.prioridade - a.prioridade || b.data_evento.localeCompare(a.data_evento)); ---

Decisão de arquitetura: como carregar o JSON
✓ Import direto (recomendado para vocé)
✓Simples: import data from '../data/assuntos.json'
✓Funciona com array raiz — sem split de arquivos
✓TypeScript valida os tipos automaticamente
✓Zero configuração extra — Astro faz o import nativo
✓Adiciona Zod manualmente para validação de build
Content Collections (alternativa)
~Requer um JSON por entrada (não array único)
~Precisa de script para split do assuntos.json
~Schema Zod nativo via defineCollection
~Melhor para projetos com muitos colaboradores
~Overkill para fonte única de JSON centralizado

Para o lawfare-timeline, o import direto é a abordagem correta: você mantém um único assuntos.json, adiciona entradas diretamente, e o Astro gera todas as páginas estáticas no build. Se um dia precisar de colaboradores externos via PR, migrar para Content Collections é simples.
